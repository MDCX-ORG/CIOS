## B.1 规模包络（L51；分期见 L68）

> **分期（L68，2026-06-14——不砍需求，只调优先级）**：实施重排为"设施侧监控优先、GPU/BMC 带内遥测后置"，规模包络随之**分两期**，两期均为冻结靶、仅启用时点不同：
> - **Phase-1（即时，设施侧）**：纯 BMS/设施侧（冷却 + 配电 + 环境），单边缘 **~1 万点/站**、单 pod **数百点**——当前 prompt 的"性能"审核按此线。
> - **Phase-2（后期，含 IT/GPU 带内）**：启用 GPU/BMC 带内遥测后切到 L51 全量靶 **≥100 万点 / 单 pod ≥3 万点**——**不变、不砍**。

| 量 | Phase-1（设施侧，当前线） | Phase-2（含 GPU/BMC，后期 = L51 全量靶） | 依据 |
|----|------|------|------|
| 单边缘（site）点位总量 | **~1 万点**（纯设施侧） | **≥100 万点**（含 GPU/BMC 带内遥测） | L51 / L68：纯设施侧约低 2 个数量级；100 万靶含 IT 带内（单 DC45 ≈2.75 万 × >30 pod） |
| 单 pod gateway 点位 | **数百点**（设施侧） | **≥3 万点**（含 IT） | DC45 含 IT ≈2.75 万 + 余量 |
| 站点数（fleet） | 设计按 ≥20 站横向扩展 | Q-S1/S2 未回，按销售口径上限预留 |
| 单站资产数 | ≥5 万（含 chip 级） | node×gpu 展开 |

## B.2 延迟与时效

| 链路 | 基线 | 备注 |
|------|------|------|
| 采集→边缘可查（VM） | ≤10s | 含换算与批写；与采样周期解耦 |
| 告警触发→通知出口 | ≤3s（边缘规则引擎内）/ ≤60s 端到端 | M1 E1.6 |
| Set 下发→回读确认 | ≤5s | spec-002 §8 |
| API P99（站点 API 读） | <500ms | 不含 PromQL 重查询（按 VM 自身预算） |
| 云端汇聚延迟（1m 降采样流） | ≤90s | M1 E1.2 之后适用 |

## B.3 资源预算

| 对象 | 基线 |
|------|------|
| pod gateway（ARM） | 3 万点@默认采样率：CPU ≤2 核稳态、RSS ≤2GB；断网 WAL 7 天不爆盘 = **L65 定稿（D10 收口）**：全量缓冲 7 天原始 ≈120–700 GB → 强制 gzip（~8–10×）压缩后 ≈15–80 GB，落 128–256 GB SSD 分区；WAL 上限配置化，默认按出厂分区，代码默认 1 GiB 仅开发用 |
| site 边缘栈（core+VM+PG+NATS） | 100 万点：单机 16C/64G 起步可承载（双机可选，spec-006）；VM 磁盘按 90 天原始保留测算 |
| CLI 命令往返 | 本地 API <1s 感知 |

## B.4 可靠性

| 项 | 基线 |
|----|------|
| 断网数据不丢窗口 | ≥7 天（M1 WAL，Exit Criteria 4） |
| gateway 单驱动崩溃 | 不影响其余驱动与主体（M1 go-plugin 后强制） |
| 边缘进程重启恢复 | ≤30s 内恢复采集（配置云端托管，零人工） |
| 数据质量 | suspect/stale 标记率可观测；全 good 轮次比例 ≥99%（健康站点稳态） |

## B.5 热路径纪律（审核执行口径）

- 采集循环内：零字典/点表重复解析（启动期预编译——PRMT-010 已立此例）
- 单点故障 fail-soft，禁止整轮失败（PRMT-009 契约已立此例）
- 禁止热路径反射/正则编译/无界分配；HTTP 客户端复用
- 采样周期一律配置（L52），代码出现硬编码周期 = 审核否决

## B.6 验证方式

- M0：基线为**设计约束**（审核对照），不做压测
- M1 E1.2 归档前：100 万点合成负载压测（modbussim/snmpsim 扩展批量模式），B.1–B.3 实测留档
- 回归：每个里程碑出口跑一次基线压测，劣化 >10% = 阻塞项
